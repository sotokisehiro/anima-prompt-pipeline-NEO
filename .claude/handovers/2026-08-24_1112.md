## 決定事項

- ファイル名はユーザー指定どおり **`BIGINER.md`**（`BEGINNER.md` ではない）
- 今回の範囲は **機能概要 + インストール手順のみ**。使い方・設定一覧・トラブルシュート大全は書かない
- Windows を主、Linux は同じ手順の短縮。`run_web.bat` / `run_llm.bat` が実入口
- インストールは 2 段:
  - A: このツールでプロンプト＋ネガティブが出るまで（Python / venv / 辞書 / llama-server）
  - B: 画像を出すために別途（ComfyUI + Anima 本体/TE/VAE）。A の完了条件には入れない
- ポートは **`config.py` の 8088 を正**（README の `:8080` は古い。写さない）
- Web は **7865**。Windows の venv 名は **`winvenv`**（`run_web.bat` が `..\winvenv` を直指定）
- 依存は **`anima_pipeline/requirements.txt`**。ルートの `requirements.txt`（requests のみ）は使わない
- 辞書パスは **`anima_pipeline/data/`**（ルートの `/data/` ではない）。一般辞書必須、artist/char は任意
- Gemma は **公式 instruct を推奨**。`run_llm.bat` の Huihui/abliterated ファイル名は手順の手本にしない
- GGUF・CSV・ビルド済み辞書は同梱しない、と明記（作業ツリーにあってもドキュメントでは各自取得）
- Forge は「置き方」だけ。`install.py` は pyahocorasick/rapidfuzz のみ。辞書と llama-server は別途必須

## 捨てた選択肢と理由

- **README のセットアップをほぼコピーする案**: 却下。README は Linux 主・`:8080`・`venv` で、Windows の `winvenv` / 8088 と食い違う
- **使い方（CLI 実行例・Web 操作）まで一気に書く案**: 却下。ユーザーが機能概要とインストールだけと指定
- **`run_llm.bat` のモデル名をそのまま載せる案**: 却下。NOTICE が公式 Gemma instruct を推奨し、bat は abliterated
- **トラブルシュート大全（OOM・思考文・日本語フォルダ名）を入れる案**: 却下。範囲外。README へ誘導のみ
- **ファイル名を `BEGINNER.md` に直す案**: 却下。ユーザー指定は `BIGINER.md`

## ハマりどころ

- README / `anima_pipeline/README.md` / `run.py` docstring は Gemma ポート **8080** と書くが、`config.py` と `run_llm.bat` は **8088**。ビギナー文書は config 側を正とした
- `run_web.bat` は `anima_pipeline/` をカレントにしないと `..\winvenv` がリポジトリ外を見る。Explorer ダブルクリックなら bat の場所が cwd になる
- PowerShell では `winvenv\Scripts\activate` ではなく `Activate.ps1`（実行ポリシーで落ちやすい）
- `run_llm.bat` の `-m` はファイル名だけ。GGUF を `anima_pipeline/` に置くかフルパスにする必要がある。「置き場所は自由」と食い違う
- agy CLI による Web 検索はタイムアウトして打ち切った。ドキュメント作成自体には不要だった

## 学び

- ビギナー文書では「コード上の実入口」（bat / config）を正にし、古い README を写さない
- 「このツールの完了」と「絵が出る完了」を混ぜると、Anima 未導入でツールが動かないように読まれる
- `app_web.py` はリポジトリルートを `sys.path` に入れるシムがあるため、`anima_pipeline` から `python app_web.py` でも import は通る
