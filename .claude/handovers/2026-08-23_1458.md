## 決定事項

- 本リポジトリ自体を拡張化する(別ディレクトリにコピーしない)。開発中は `mklink /J C:\aiwork\sd-webui-forge-neo\extensions\anima-prompt-pipeline C:\aiwork2\anima-prompt-pipeline` でジャンクション導入
- 履歴管理はサーバー側 JSON 保存(`user_data/history.json`)。旧 localStorage + CSV(BOM付きUTF-8, CRLF)とは CSV 経由で相互運用可能にする
- プロンプト送信先は txt2img と img2img の両方(タブ自動切替 + プロンプト/ネガティブ上書き)
- 既存の FastAPI 版 Web GUI(`app_web.py` + `web/`)と CLI(`run.py`)は残し、動作を維持する(拡張版と共存)
- パッケージ内部は相対 import、エントリスクリプト(run.py/app_web.py)は sys.path シム + 絶対 import という使い分け
- パイプラインインスタンスは `fuzzy_cutoff` が変わらない限りキャッシュ再利用(`service.py`)。他パラメータは `run()` の引数化で都度渡す設計に変更
- 拡張タブでは重い依存(`anima_pipeline.service`/`pipeline`)の import を生成ボタンハンドラ内まで遅延させ、依存導入に失敗してもタブ自体は表示されるようにする

## 捨てた選択肢と理由

- **Forge 側に新規ディレクトリで拡張を作る案**: 却下。本リポジトリと二重管理になり同期コストが発生するため、本リポジトリ自体を拡張化する方式を採用
- **リポジトリ内に extension/ サブディレクトリを作りそこだけをリンクする案**: 却下。パイプラインコード共有の仕組みが複雑になるため、リポジトリルート直下に `scripts/`/`install.py`/`javascript/` を追加する素直な方式にした
- **履歴を localStorage のまま維持する案**: 却下。Gradio 4 での localStorage 連携はカスタム JS が複雑になるため、サーバー側 JSON 保存 + CSV 互換の方式を採用
- **絶対 import(`anima_pipeline.x` 形式)に全部統一しパッケージ内部でも使う案**: 検討したが、パッケージ内部は相対 import の方が「anima_pipeline というパッケージ名自体」が何かに衝突しても安全という利点があり、内部は相対・エントリだけ絶対、という使い分けにした
- **`AnimaPipeline()` を拡張タブ構築時に毎回/常時初期化する案**: 却下。辞書ロード+Aho-Corasick構築が重く Forge 起動を遅くするため、初回生成時に遅延構築してキャッシュする設計にした

## ハマりどころ

- `generate.py::ChatClient.chat` の `temperature`/`max_tokens` がデフォルト引数値として **import 時に** `config.GEN_TEMPERATURE`/`GEN_MAX_TOKENS` に固定されるバグがあり、旧 `app_web.py` の「リクエストごとに config を書き換えて戻す」実装がこの2つのパラメータに対して無効(no-op)だった。今回 None デフォルト + 呼び出し時解決に変更して修正
- `service.py` のキャッシュキー比較で、`fuzzy_cutoff=None` のまま `AnimaPipeline` が解決した実効値と比較すると常にキャッシュミスするバグの芽があった。呼び出し前に `effective = fuzzy_cutoff if fuzzy_cutoff is not None else config.SNAP_FUZZY_CUTOFF` を計算してから比較するよう設計段階で修正済み
- Forge NEO 拡張ローダーは拡張ルートを自動で `sys.path` に追加する(`modules/scripts.py`)ため理論上シム不要だが、念のため `scripts/anima_prompt_pipeline.py` 側にも保険のシムを入れた

## 学び

- Forge NEO(`C:\aiwork\sd-webui-forge-neo`)は Gradio 4.40.0、Python 3.13.12(venv: `C:\aiwork\sd-webui-forge-neo\venv`)。同居する reForge(`C:\aiwork\stable-diffusion-webui-reForge`)は Gradio 3.41.2、Python 3.10.11 と別物なので混同注意
- Forge の拡張は `extensions/<name>/scripts/*.py` が自動ロードされ、`script_callbacks.on_ui_tabs(callback)` で独立タブを追加できる。`callback` は `[(gr.Blocks, title, elem_id), ...]` を返す
- 送信先メイン UI への反映は `javascript/ui.js` の `switch_to_txt2img()`/`switch_to_img2img()` + `updateInput(target)` の組み合わせが定番パターン(`extensions/ScribeNEO` に実装例あり)。`updateInput` を呼ばないと Gradio の Python 側 state に反映されない
- `install.py` は Forge 起動時に自動実行され、`launch.is_installed`/`launch.run_pip` で依存を追加できる(`pyahocorasick` は Python 3.13 でも 2.3.1 が対応)
- ユーザーのグローバル CLAUDE.md 指示: 「プラン作成・オーケストレーションは Fable、その他の作業(コード作成・テスト)は sonnet5」→ 実装フェーズは全て `model: sonnet` の Agent 呼び出しに委譲する運用を徹底した
