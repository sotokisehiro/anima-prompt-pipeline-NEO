## 決定事項

- 接続先の優先順位: `run(chat_url=)` / CLI `--server` > 保存済み設定 > `config.CHAT_URL`(既定値として残す)
- 保存は 1 ファイル(`user_data/settings.json`)で Web GUI / Forge / CLI が共有
- UI は URL を `config` から直接読まず、必ず `settings_store.get_chat_url()` を使う
- `service.py` のキャッシュキーに URL は含めない(URL を変えても辞書再構築しない)
- Forge の生成に使うのは**保存済みの値**。入力欄を編集しただけで未保存の値は使わない
- `settings_store.py` は標準ライブラリ + `config` のみ(Forge のタブ構築時に import しても軽い)
- CLI `--server` は保存しない

## 捨てた選択肢と理由

- **Web の URL をブラウザ localStorage に保存**: 却下。Gemma に接続するのは FastAPI サーバー側で、Forge / CLI と共有できない
- **`config.py` を書き換えて永続化**: 却下。ソース編集を避けるのが目的
- **URL をキャッシュキーに含めて `AnimaPipeline` を作り直す**: 却下。辞書ロード + Aho-Corasick 構築が重い。URL は呼び出し時に渡せば足りる
- **Forge で未保存の入力欄の値をそのまま生成に使う**: 却下。状態表示と実際の接続先が食い違う
- **CLI `--server` で保存まで行う**: 却下。1 回限りの上書きにして、保存は GUI に任せる

## 学び

- 「デフォルト引数に `config.X` を書く」と import 時に固定される。設定を後から変えたい値は `None` デフォルト + 呼び出し時解決にする(temperature と同じ規約)
- Gradio の `value=` はタブ構築時に固定されるため、他の入口で変わる値は `anima_tab.load` で読み直す
