## ハマりどころ

- Windows ジャンクションは `Path.is_symlink()` が **False**。Gradio 4 `utils.abspath()` は相対 `file=` を `path.resolve()` し、実体 `C:\aiwork2\...` になって 403
- 絶対パス `file=C:/aiwork/sd-webui-forge-neo/extensions/anima-prompt-pipeline/javascript/...` は 200（junction 側パスのまま）。相対 `file=extensions\anima-prompt-pipeline\javascript\...` が 403 だった
- ScribeNEO / couple の相対 `file=` は 200（Forge 配下に実体があるため）
- `Start-Process` で stdout/stderr を同一ファイルへリダイレクトすると失敗。out/err を分ける
- PowerShell ラッパーでは `$ProgressPreference` の `$` が消え、`function Try` は予約語と衝突
- Chrome `--dump-dom` だけでは `typeof anima_send_to` を確認できない。CDP（port 9223 + Node 組み込み WebSocket）で評価した
- ダミー `_js="() => {}"` は HTML 文字列検索では見つからないことがある。`gradio_config.dependencies` では `js: '() => {}'`, `backend_fn: false`, `inputs/outputs: []`
- ジャンクション経由の `read_file` は Permission deny することがある。`Get-Item` / `dir` は通る

## 学び

- Forge 拡張 JS が動かないときは、まず HTML の `<script src="file=...">` を **GET して status を見る**。403 なら関数未定義でボタン無反応になる
- Gradio 4 の `/file=` 許可は `blocks.allowed_paths`。Forge は `cmd_opts.gradio_allowed_path` を `launch(allowed_paths=...)` に渡す。ジャンクション開発では `on_before_ui` で realpath を足す
- 送信は `updateInput` 必須。値を入れただけでは A1111 の内部 state に乗らない
- 調査仮説: H3（JS 403）が直接原因。H2（Gradio 4 の js= 配線）は二次で今回一緒に直した。H1 は弱い（イベント JSON はあったが関数が無い）。H4–H6 は JS ロードまで到達不能だった
